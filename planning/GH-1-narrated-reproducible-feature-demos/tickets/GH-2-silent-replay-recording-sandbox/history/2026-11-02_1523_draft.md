# Replay a demo script on a virtual display and write a silent MP4 with step timings

## Problem

There is no way to record an agent's demo headlessly and reproducibly: the existing `screen-recording` skill assumes
OBS on a person's desktop.

## Change

- The container image: virtual display, Chromium, Playwright, ffmpeg.
- The npm package `flow-reel` with the `demo()` / `step()` API (decision 010) and the CLI: on the host,
  `flow-reel record demo.ts` starts the image with the project mounted; inside, it replays the script and records.
- The runner's stabilisation from decision 009: fixed viewport and device scale, `prefers-reduced-motion`, fixed
  clock and seed, network-idle wait before each step.
- `transcript.json` with `video` and each step's `index`, `startMs`, `actionEndMs`, `endMs` (decision 011).

## Out of scope

Narration, captions, audio (tickets 2-4).

## Done when

- `flow-reel record` on a sample app writes a silent 1920×1080 MP4 and a `transcript.json` that validates against
  schema version 1.
- Two runs of the same script have the same steps, every start within ±150 ms.

## For the ticket pass

- The recorder: Xvfb + ffmpeg `x11grab`, or Playwright `recordVideo` / CDP screencast (quality, frame pacing).
- Reaching an app on the host (`--network host`, `host.docker.internal`) on Linux, macOS and WSL2.
- Image size, base image, multi-arch builds, Docker and Podman.
