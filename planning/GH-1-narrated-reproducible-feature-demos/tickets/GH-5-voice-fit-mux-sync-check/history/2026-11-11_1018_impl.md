## Current code and baseline

- `src/runner/run.ts` captures once, calibrates times against a green marker, writes a silent delivery MP4, closes
  browser/display, and calls `voiceSteps`. Narration is only discovered as `step()` executes.
- `actionEndMs` and `endMs` currently coincide. Network idle is checked before a step, not after its callback.
  `trackNetwork().idle()` already supplies 500 ms quiet / 10 s timeout behavior.
- GH-4 writes portable `<name>.audio/NNN.wav` clips and version 1 voice/audio metadata. The selected Qwen/Ryan/
  English CPU runtime, seed, original narration and WAV hashes are settled; do not change the worker or its pins.
- `.flow-reel/<name>/master.mp4` currently contains calibration pre-roll. `master.json.startMs` identifies where
  delivery time zero starts in it. The current events and captions use calibrated delivery-relative times.
- `src/cli.ts` only routes `record`; the host launcher starts Docker/Podman. No comparison or sync checker exists.
- Baseline: all 50 unit tests and type checking pass. The script-loader subprocess failed inside the sandbox and
  passed on rerun outside. Docker E2E was not repeated for planning; merged GH-4 CI passed its full media suite.

## Implementation shape

Keep the reusable boundaries small: a pure timeline planner (`src/runner/timeline.ts`), media rendering
(`src/runner/render.ts`), semantic sync validation (`src/schema/sync.ts`) and pure comparison (`src/compare.ts`).
The CLI only reads files, calls comparison and maps its result to an exit code. Reuse existing capture, synthesis,
caption serialization and schema validation. No generic editing engine, provider framework or new public options.

## Steps

1. **Capture a settled visual window without changing action identity.** In `run.ts`, retain `actionEndMs` at
   callback return, then perform the bounded idle wait plus 100 ms capture from decision 003. Save that visual
   endpoint for the planner. Warn on idle timeout, as the existing before-step wait does. Keep capture's overload
   guard, calibration and single execution of the body. Expensive synthesis/rendering occurs after capture and
   browser/display shutdown.
   → check: add a focused real-browser fixture with an action that returns before a delayed response updates the
   UI. Observe failure before this change, then verify the captured endpoint includes the settled result while
   actionEndMs still denotes callback return. A blank-narration fixture can exercise this without running Qwen.
   Use an even-scaled viewport and bounded container cleanup, following GH-4's harness pattern.

2. **Plan frame-exact holds and one timestamp mapping.** Add a pure planner taking calibrated captured steps,
   source video frame count/FPS and the delivery cut offset. Quantize each captured visual endpoint upward to a
   source frame boundary. Preserve the original calibration pre-roll. A hold is inserted after the final frame
   of that step's captured window, before subsequent source frames. Compute the deficit from clip duration plus
   200 ms versus that window; add only enough whole frames, with no speech padding for blank steps.
   Return hold boundaries/counts, final step times and a source-to-final timestamp mapping. Apply prior holds to
   each start/actionEnd; endMs includes its visual window and own hold. Preserve source WAV metadata. Map every
   event, including events in gaps, exactly once; preserve coordinates, action durations and typing cadence.
   Derive durations from integer frame/sample counts rather than cumulative rounded millisecond additions.
   → check: failing unit slices in `test/unit/timeline.test.ts` before implementation. At 30 fps, a step starting
   at 500 ms with visual end 1000 ms and a 1000 ms clip needs 21 added frames: final end 1700 ms, and an original
   next start at 1200 ms becomes 1900 ms. Cover fractional-frame boundaries, multiple holds, long actions, blank/
   empty steps, zero-duration callbacks with a visual settle window, final-step holds, nonzero pre-roll, events
   before/after each boundary, unchanged event durations and nonmutation. Expected frame counts must be worked
   examples, not recomputed copies of the planner's own algorithm.

3. **Add shared sync and comparison checks.** Preserve the existing version 1 validator's compatibility; add
   semantic checks at the new boundary. Require positive video dimensions/FPS, ordered nonoverlapping step
   windows within the video, and startMs <= actionEndMs <= endMs. Audio must have usable hash/duration metadata,
   fit within its step with the 200 ms tail, and never reach the next step. Voiced recordings must have clips for
   nonblank narration; legacy silent transcripts without a voice remain comparable. Blank-only configured voice
   is valid without clips. Comparison reads metadata, not referenced audio/caption files.
   Compare width/height/FPS, step count/index/order, exact optional narration, optional voice identity (adapter,
   voice, seed), clip presence/hash/duration, and each start within 150 ms inclusive. Ignore script/output paths;
   do not compare raw caption files whose timestamps legitimately differ. End/actionEnd/video duration must be
   internally valid but are not additional equality tolerances beyond story decision 009. State this limit.
   Return separate validation errors and content differences so CLI can use 0 = valid/equal, 1 = valid/different,
   2 = invalid input/usage (including unreadable JSON or failed sync).
   → check: `test/unit/sync.test.ts` and `compare.test.ts` cover overlap, truncated clips, missing voiced metadata,
   reversed/out-of-video times, exact 150 ms acceptance and 151 ms rejection, text/order/voice/hash/duration changes,
   relocated paths, blank-only and legacy silent inputs, and malformed input. Build one behavior at a time.

4. **Render the held master and placed narration with existing FFmpeg.** Record the original capture to
   `.flow-reel/<name>/capture.mp4`. Render `master.mp4` at the same resolution and 30 fps using the planned frame
   spans/holds. Preserve its leading calibration frames and `master.json.startMs` offset, so delivery-relative
   final events remain usable by GH-7. Check rendered frame counts against the plan. Use frame-index trim/PTS
   operations for cuts and holds (e.g. trim + tpad clone + concat), rather than accumulating imprecise seeks.
   Produce the delivery video with the existing Lanczos downscale, H.264 quality and fast-start behavior.
   Assemble original clips at final step starts as a 48 kHz stereo PCM voice bus, pad/trim to video length, then
   perform measured two-pass loudnorm (-16 LUFS, LRA 11, peak ceiling -1.5 dBTP). Keep normalized `voice.wav` under
   the work folder for later rendering/SFX; public audio metadata still references original source WAVs. Encode

   Measure decoded delivery loudness and true peak. Use an explicit pre-encode peak margin if needed for AAC

   → check: a small synthetic-media test in `test/e2e/render.test.ts`, without Qwen or a browser. Use known color

## Risks

- Repeating actions to discover text would repeat side effects: keep synthesis after the only replay.
- Callback return/network quiet is not proof of business success. Scripts await intended state; capture the
  bounded settle window before its held frame, and retain the timeout warning policy.
- Off-by-one frame cuts, AAC priming/padding and double-applied timestamp shifts can desynchronize output. Use
  integer frame/sample planning, synthetic decoded-output checks, and the existing real click/frame assertion.
- A retimed delivery file with an unretimed master/events would break GH-7/GH-8. Produce those artifacts together,
  preserving the master's cut-offset meaning and original source clips.
- Normalization can change level after lossy encoding. Measure decoded delivery, keep raw hashes intact and
  explicitly handle silence. Source-clip equality does not claim identical encoded MP4/audio bytes.
- CPU TTS remains costly and capture still needs spare CPU. Render after capture/model execution; measure render
  memory/runtime and avoid running expensive E2E files concurrently. Do not weaken capture-overload checks.
- Transcript comparison cannot prove visual/semantic UI equality or audit referenced file bytes. Document the
  inherited structural/audio-metadata/step-start rule without broadening it into perceptual comparison.
